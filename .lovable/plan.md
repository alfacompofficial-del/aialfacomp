# Три новые возможности Nexus

## 1. Анализ любых ссылок (включая GitHub-репозитории)

Новый инструмент агента `analyze_repo` + улучшенный `fetch_url`:

- Пользователь кидает ссылку вида `https://github.com/owner/repo` (или ссылку на папку/файл/ветку) и просит «проанализируй все файлы, найди ошибки».
- Агент через GitHub API получает дерево файлов, выбирает до ~40 текстовых файлов кода (пропускает бинарники, `node_modules`, `dist`, lock-файлы, файлы >100 КБ), скачивает их содержимое и передаёт модели.
- Модель выдаёт отчёт: структура проекта, стек, найденные ошибки/риски/уязвимости, что улучшить — со ссылками на конкретные файлы и строки.
- Для очень больших репозиториев — анализ по приоритету (входные точки, конфиги, самые крупные модули) и явное предупреждение, что охвачена часть файлов.
- Любая другая ссылка (сайт, статья, gist, npm-пакет, docs) идёт через уже существующий `fetch_url`, который расширим: определение типа контента, извлечение основного текста, поддержка JSON/plain text, ссылки на изображения передаются в модель как изображения.

## 2. Публикация проектов пользователя по ссылке `/site/{name}`

- В блоке кода HTML/CSS/JS рядом с «Протестировать» появляется кнопка **«Создать ссылку»**.
- Открывается окно с полем имени проекта. Проверка: разрешены `a-z 0-9 -`, длина 3–40. Если имя занято — ошибка «Это имя уже занято», если свободно — публикация.
- Ссылка вида `https://<домен>/site/my-landing` — открывает страницу с проектом на весь экран (рендер в изолированном iframe в режиме sandbox).
- Страница «Мои сайты» в меню: список опубликованных проектов, копирование ссылки, обновление кода, удаление.
- Публичный просмотр доступен всем по ссылке; создавать и изменять может только владелец.

## 3. Настройки общения (личные инструкции для ИИ)

- Новая страница/панель **Настройки** (иконка в сайдбаре чата):
  - Поле «Как со мной общаться» (свободный текст, до 2000 символов) — например «не подлизывайся, спорь со мной, отвечай кратко».
  - Быстрые переключатели-пресеты: тон (нейтральный / дружелюбный / жёсткий критик), длина ответа (кратко / обычно / подробно), язык ответа, «всегда указывать источники», «сразу давать код без вступлений».
  - Имя/как обращаться к пользователю.
- Настройки сохраняются в профиле пользователя и автоматически подставляются в системный промпт каждого запроса (в чате и в `/think`), не ломая базовые правила безопасности.
- Кнопка «Сбросить настройки».

## Технические детали

- **БД:** новая таблица `user_settings` (`user_id`, `custom_instructions`, `tone`, `verbosity`, `language`, `preferred_name`, флаги) с RLS «только свои» и GRANT для `authenticated`; новая таблица `published_sites` (`id`, `user_id`, `slug` unique, `html`, `css`, `js`, `title`, `created_at`, `updated_at`) — публичный SELECT для `anon`/`authenticated`, INSERT/UPDATE/DELETE только владельцу. Лимит: 10 сайтов на пользователя (проверка триггером/в edge-функции).
- **Агент** (`supabase/functions/_shared/nexus-agent.ts`): добавить инструмент `analyze_repo` (GitHub API `git/trees?recursive=1` + `raw.githubusercontent.com`, использовать `GITHUB_TOKEN`, если задан), расширить `fetch_url`; системный промпт собирать как база + пользовательские настройки (загружаются в `chat/index.ts` по `userId`).
- **Публикация:** edge-функция `publish-site` (проверка slug, upsert, лимит) — используется кнопкой в `CodeBlock`. Роут `/site/:slug` в `App.tsx` рендерит `srcDoc` в sandbox-iframe (`allow-scripts` без `allow-same-origin`).
- Ключи/секреты не нужны — GitHub API работает и без токена (лимит 60 запросов/час на IP); при желании позже добавим `GITHUB_TOKEN` для лимита 5000/час.
