# Большое обновление Nexus: превью, OCR, песочница, GitHub, голос, версии, скорость

Работу делим на 3 этапа, чтобы каждый можно было проверить отдельно.

## Этап 1 — Чат и скорость (самое заметное)

1. **Миниатюры картинок** — вместо текста «pasted-image.png» в сообщении показывается превью; по клику открывается на весь экран (с закрытием по Esc / клику).
2. **Редактирование и удаление промптов** — у своего сообщения кнопки «Изменить» и «Удалить». Удаление плавное (анимация исчезновения). После правки ответ ИИ генерируется заново.
3. **Версии чата (откат)** — при правке старого сообщения прежняя ветка сохраняется; стрелки «‹ 1/3 ›» под сообщением переключают версии, можно вернуться к прежнему состоянию.
4. **Плавные анимации** — появление сообщений, курсор при печати, плавная прокрутка (CSS-переходы, без тяжёлых библиотек).
5. **Скорость**:
   - первый символ ответа показывается сразу (индикатор «печатает» + стриминг уже есть, уберём лишние ожидания перед ответом — настройки и история грузятся параллельно);
   - кэш анализа GitHub-репозиториев на 1 час — повторный вопрос по тому же репо не скачивает файлы заново;
   - длинная история автоматически сжимается: старые сообщения заменяются кратким конспектом, чтобы не терять начало разговора и не тормозить.

## Этап 2 — Умные функции

6. **OCR скриншотов** — при отправке картинки с текстом/ошибкой ИИ распознаёт текст; под ответом появляются кнопки **«Копировать текст ошибки»** и **«Исправить эту ошибку»** (отправляет готовый запрос одним нажатием).
7. **Живая песочница с ползунками** — в превью HTML/CSS добавляется панель «Настроить»: автоматически находит цвета и длительности анимаций в коде и даёт палитру/ползунки; изменения видны сразу, кнопка «Скопировать изменённый код».
8. **Голос**:
   - кнопка микрофона в поле ввода — надиктовать задачу (распознавание речи);
   - кнопка «Озвучить» у ответа — короткая аудио-сводка (ИИ сжимает ответ до 2–3 фраз и зачитывает).

## Этап 3 — Действия в ваших сервисах

9. **«Применить к GitHub» (Pull Request)** — у предложенной правки появляется кнопка; Nexus создаёт ветку, коммит и Pull Request в ваш репозиторий. Для этого каждый пользователь один раз вводит свой GitHub-токен в Настройках (хранится зашифровано на сервере, только у владельца).
10. **«Применить к Supabase»** — у SQL-блока кнопка, которая выполняет миграцию в **ваш собственный** Supabase-проект (пользователь указывает адрес проекта и ключ доступа в Настройках). Перед выполнением — окно подтверждения с показом SQL. Внутреннюю базу Nexus эта кнопка не трогает.

## Также доделаю (обещано ранее)
- Время размышления 5–15 минут в Настройках + таймер «Думаю: 3:42 из 10:00».
- Обновление внешнего API (`nx_live_...`) до текущей версии агента.

## Честно об ограничениях
- «50 000 файлов» в одном запросе невозможно ни у одной модели; сделаем умный отбор + конспект + кэш, это даёт тот же эффект на практике (сотни файлов по частям).
- Голос и OCR тратят AI-кредиты чуть больше обычного сообщения.

## Технические детали
- Новые таблицы: `message_versions` (ветки сообщений), `repo_cache` (кэш дерева/файлов, TTL 1ч), `user_integrations` (GitHub/Supabase токены, RLS — только владелец, токены читаются только edge-функциями).
- Edge-функции: `transcribe` (`openai/gpt-transcribe`), `tts` (`google/gemini-3.1-flash-tts-preview`), `github-pr` (Git Data API: blobs → tree → commit → ref → pulls), `apply-sql` (выполнение через Management API пользовательского проекта с его токеном).
- OCR: в агенте инструкция для картинок — возвращать распознанный текст в блоке ```ocr, фронт рендерит его кнопками.
- Сжатие контекста: при >30 сообщениях старые сворачиваются в summary быстрой моделью, кэшируется в чате.
- Песочница: парсинг hex/rgb цветов и `\d+(ms|s)` в CSS, подстановка через postMessage в iframe.
